# CH14 — I/O

## 1) Overview

Java has **two parallel I/O hierarchies**:

- **`java.io`** — the original streams and readers/writers (bytes vs. chars).
- **`java.nio.file`** — the modern NIO.2 API based on `Path` and the `Files` utility class.

The OCP exam mixes both: stream chaining, character vs. byte handling, file traversal with `Files.walk` / `Files.find`, and serialization rules.

---

## 2) Key Concepts

### `java.io` Streams

Two orthogonal axes:
1. **Direction**: input vs. output.
2. **Format**: byte (`InputStream`/`OutputStream`) vs. character (`Reader`/`Writer`).

| Type | Reads byte | Reads char |
| --- | --- | --- |
| Input | `InputStream` | `Reader` |
| Output | `OutputStream` | `Writer` |

Common concrete classes:
- **Files**: `FileInputStream`, `FileOutputStream`, `FileReader`, `FileWriter`.
- **Buffered**: `BufferedInputStream`, `BufferedOutputStream`, `BufferedReader`, `BufferedWriter`.
- **Data**: `DataInputStream`, `DataOutputStream` (primitives in binary form).
- **Object**: `ObjectInputStream`, `ObjectOutputStream` (serialization).
- **Print**: `PrintStream` (e.g. `System.out`), `PrintWriter`.

### Bridge Streams

- `InputStreamReader` wraps an `InputStream` to produce a `Reader`.
- `OutputStreamWriter` wraps an `OutputStream` to produce a `Writer`.
- Both accept a `Charset` (e.g., `StandardCharsets.UTF_8`).

### `java.nio.file` Path & Files

- `Path` (interface) is created via `Path.of(...)` or `Paths.get(...)`.
- `Files` is a utility class with static methods for almost every common operation:
  - **Read/Write**: `readString`, `writeString`, `readAllLines`, `readAllBytes`, `lines` (Stream), `newBufferedReader`, `newBufferedWriter`.
  - **Existence**: `exists`, `notExists`, `isDirectory`, `isRegularFile`, `isReadable`, `isWritable`.
  - **Manipulation**: `createDirectory`, `createDirectories`, `delete`, `deleteIfExists`, `copy`, `move`.
  - **Walking**: `list`, `walk` (recursive, depth-controlled), `find` (predicate-filtered), `walkFileTree` (visitor pattern).
  - **Metadata**: `size`, `getLastModifiedTime`, `getOwner`, `readAttributes`.

### Serialization

- A class implements `java.io.Serializable` to be serialized.
- All non-`transient`, non-`static` fields are serialized.
- The class needs a `serialVersionUID` (`private static final long`) — recommended to declare explicitly.
- Subclasses inherit serializability if the parent is `Serializable`.
- If the **parent is NOT serializable**, the parent must have a no-arg constructor; on deserialization, that no-arg constructor runs to reconstruct the parent state.
- `transient` fields are skipped (left null/default after deserialize).
- `Externalizable` is the alternative giving you full control of read/write.

### Console I/O

- `System.in` (InputStream), `System.out`/`System.err` (PrintStream).
- `Console` (`System.console()`) — interactive password reading and prompting; **null** in non-interactive contexts.
- `Scanner` for parsed input (`nextInt`, `nextLine`).

### `try-with-resources` for I/O

All file/stream classes implement `AutoCloseable`. Always use try-with-resources to guarantee close.

## 3) Important Rules

- A `Reader`/`Writer` handles **chars** (16-bit), an `InputStream`/`OutputStream` handles **bytes**. Mixing requires bridge streams.
- Buffered streams are not auto-flushed on close — but their `close()` *does* flush. `PrintWriter` auto-flush is opt-in via constructor.
- `Files.lines(path)` returns a `Stream<String>` that is **lazy** — must be closed (use try-with-resources).
- `Files.walk(path)` uses lazy DFS; you must close that stream too.
- `Path.of("a", "b")` is platform-aware (`a/b` on Linux, `a\b` on Windows).
- `Path.resolve(other)` joins; `Path.relativize(other)` produces a relative path.
- Serialization recursively traverses — every reachable non-transient field must be `Serializable`, otherwise `NotSerializableException`.
- A serialized object's class must remain compatible with its `serialVersionUID`. Mismatched UIDs cause `InvalidClassException`.
- `transient` fields are **default-initialized** after deserialization (null for refs, 0 for primitives, etc.).
- `static` fields are not part of the serialized form — they belong to the class, not the instance.
- `Files.newBufferedReader(path)` defaults to UTF-8 (Java 17+).
- `FileReader`/`FileWriter` use the platform default charset unless you pass a `Charset`.
- `Files.copy(src, dst)` fails if `dst` exists unless you supply `StandardCopyOption.REPLACE_EXISTING`.

## 4) Code Examples

### Read a text file

```java
Path p = Path.of("notes.txt");
List<String> lines = Files.readAllLines(p, StandardCharsets.UTF_8);
String all = Files.readString(p);
```

### Write a text file

```java
Files.writeString(Path.of("out.txt"), "hello\n", StandardCharsets.UTF_8);
Files.write(Path.of("lines.txt"),
            List.of("one", "two", "three"),
            StandardCharsets.UTF_8,
            StandardOpenOption.APPEND);
```

### Buffered character I/O

```java
try (BufferedReader br = Files.newBufferedReader(Path.of("data.txt"));
     BufferedWriter bw = Files.newBufferedWriter(Path.of("copy.txt"))) {
    String line;
    while ((line = br.readLine()) != null) {
        bw.write(line);
        bw.newLine();
    }
}
```

### Streaming a file's lines (lazy)

```java
try (Stream<String> lines = Files.lines(Path.of("big.txt"))) {
    long count = lines.filter(s -> !s.isBlank()).count();
}
```

### Walking a directory

```java
try (Stream<Path> tree = Files.walk(Path.of("/var/log"), 2)) {
    tree.filter(Files::isRegularFile)
        .filter(p -> p.toString().endsWith(".log"))
        .forEach(System.out::println);
}
```

### Serialization

```java
class Account implements Serializable {
    private static final long serialVersionUID = 1L;
    String owner;
    transient String password;
}

try (ObjectOutputStream out = new ObjectOutputStream(
        Files.newOutputStream(Path.of("acc.ser")))) {
    out.writeObject(new Account());
}

try (ObjectInputStream in = new ObjectInputStream(
        Files.newInputStream(Path.of("acc.ser")))) {
    Account a = (Account) in.readObject();
}
```

### Bridge with charset

```java
try (InputStream in = Files.newInputStream(Path.of("data.bin"));
     Reader r = new InputStreamReader(in, StandardCharsets.ISO_8859_1)) { ... }
```

### Tricky: `Path.resolve` semantics

```java
Path a = Path.of("/home/user");
Path b = a.resolve("docs/file.txt");      // /home/user/docs/file.txt
Path c = a.resolve("/etc/passwd");        // /etc/passwd  (absolute wins)
```

### Tricky: copying with options

```java
Files.copy(src, dst,
    StandardCopyOption.REPLACE_EXISTING,
    StandardCopyOption.COPY_ATTRIBUTES);
```

### Tricky: parent constructor on deserialization

```java
class A { A() { System.out.println("A ctor"); } }
class B extends A implements Serializable { ... }
// On readObject for B, A's no-arg constructor runs (A is NOT Serializable)
// If A had no no-arg constructor → InvalidClassException
```

## 5) Common Mistakes

- ❌ Forgetting to close `Files.lines(...)` — leaks file handles.
- ❌ Reading bytes with a `Reader` (or chars with an `InputStream`).
- ❌ Forgetting `serialVersionUID` — JVM generates one, which breaks across compiles.
- ❌ Marking `transient` on a primitive field expecting it to vanish — it does, but defaults to `0`/`false`, not "missing".
- ❌ Using `FileReader`/`FileWriter` and assuming UTF-8 (it's the platform default unless you pass a `Charset`).
- ❌ Calling `Path.resolve(absolute)` and being surprised that the absolute path replaces the base.
- ❌ Forgetting that `Files.copy` won't overwrite without `REPLACE_EXISTING`.
- ❌ Using `Files.walk` without limiting depth on huge trees.
- ❌ Catching `IOException` and ignoring it — use proper handling.
- ❌ Trying to serialize something that holds a reference to a non-`Serializable` object.

## 6) Mental Model

The two I/O families are **two layers**:

- `java.io` is **stream-centric**: you open a stream, you decorate it (buffered, data, object), you read/write, you close.
- `java.nio.file` is **path-centric**: you describe a file/directory and ask the static `Files` API to do something to it. The result is often a stream, list, or boolean.

For everyday code, prefer `java.nio.file`. Reach for `java.io` for legacy APIs or precise control over decoration.

For text vs. binary:
- Text → `Reader`/`Writer` (or `Files.readString` / `Files.lines`).
- Binary → `InputStream`/`OutputStream` (or `Files.readAllBytes`).
- Mixed → bridge with `InputStreamReader` / `OutputStreamWriter`.

Serialization is best avoided in modern systems (favor JSON, Protobuf, etc.), but the exam still tests the rules: `serialVersionUID`, `transient`, parent-constructor invocation when the parent is non-`Serializable`.

---

## 7) Quick Revision

- Two hierarchies: `java.io` (streams) and `java.nio.file` (Path/Files).
- Bytes → `InputStream`/`OutputStream`. Chars → `Reader`/`Writer`.
- `Files.readString`, `readAllLines`, `lines` for text; `readAllBytes` for binary.
- `Files.walk` and `find` are lazy streams — close them.
- `Path.resolve(absolute)` replaces the base; `relativize` is the inverse of `resolve`.
- Serialization: declare `serialVersionUID`, mark non-serializable fields `transient`.
- Non-serializable parents must have a no-arg constructor.
- `static` and `transient` fields are not serialized.
- `FileReader`/`FileWriter` default to platform charset; specify UTF-8 explicitly.
- Always wrap I/O in `try-with-resources`.
