# CH12 — Modules

## 1) Overview

The **Java Platform Module System (JPMS)** was introduced in Java 9 to give large applications strong encapsulation and reliable configuration. A module is a named, self-describing collection of packages with explicit dependencies. The exam tests `module-info.java` syntax, the various module *kinds* (named, automatic, unnamed), and the command-line tooling (`javac`, `java`, `jmod`, `jlink`, `jdeps`).

---

## 2) Key Concepts

### `module-info.java` Directives

Placed at the **root** of a module's source tree. Compiled to `module-info.class`.

| Directive | Purpose |
| --- | --- |
| `module name { ... }` | Declares the module |
| `requires X;` | Read access to module `X` |
| `requires transitive X;` | Re-exports the read-edge to consumers (implied readability) |
| `requires static X;` | Compile-time only (optional at runtime) |
| `exports pkg;` | Makes `pkg`'s public types visible to all modules |
| `exports pkg to A, B;` | Qualified export — only A and B see it |
| `opens pkg;` | Allows reflective access (deep) at runtime |
| `opens pkg to A, B;` | Qualified opens |
| `provides X with Y;` | Service implementation |
| `uses X;` | Service consumer |

### Module Kinds

| Kind | Source | Behavior |
| --- | --- | --- |
| **Named** | Has `module-info.java` | Standard JPMS module |
| **Automatic** | A jar on the **module path** without `module-info.java` | Name derived from filename or `Automatic-Module-Name` MANIFEST entry; *exports everything*, *requires every named module on path* |
| **Unnamed** | Anything on the **classpath** | All classes belong to one giant unnamed module; can read everything; cannot be required by named modules |

### Readability vs. Accessibility

- **Readability:** `A requires B` — A's classloader can see B's exported types.
- **Accessibility:** Beyond readability, B must `exports` the package containing the type. `public` is no longer enough on its own.

### `requires transitive` (Implied Readability)

If module **C** `requires transitive B`, then any module that does `requires C` also implicitly reads B.

### `requires static`

A compile-time-only dependency. The module loads at runtime only if present, otherwise treated as absent (no error). Useful for optional integrations.

### Services (Loose Coupling)

```java
// Provider module
provides com.foo.PaymentGateway with com.foo.impl.StripeGateway;

// Consumer module
uses com.foo.PaymentGateway;

// At runtime
ServiceLoader.load(PaymentGateway.class).forEach(...);
```

### Common Tooling

| Command | Purpose |
| --- | --- |
| `javac -d out --module-source-path src $(find src -name "*.java")` | Compile multi-module |
| `java --module-path mods -m mymod/com.foo.Main` | Run a module |
| `java -p mods -m mymod/com.foo.Main` | Short form |
| `jar --create --file mymod.jar --main-class=com.foo.Main -C out/mymod .` | Package |
| `jmod create --class-path ... mymod.jmod` | Build a JMOD |
| `jlink --module-path mods --add-modules mymod --output runtime` | Custom runtime image |
| `jdeps --module-path mods mymod.jar` | Dependency analyzer |
| `jdeps --jdk-internals app.jar` | Detect internal API usage |

### Common JDK Modules

- `java.base` — implicitly required by every module (collections, I/O, lang).
- `java.logging`, `java.sql`, `java.xml`, `java.desktop`.
- Aggregator: `java.se` (transitively requires the SE modules).

## 3) Important Rules

- Every module implicitly `requires java.base`.
- A package may only be declared in **one** module — *split packages* are illegal.
- A module may be **named** *or* **automatic** *or* **unnamed**, never two at once.
- A class on the classpath (unnamed module) **cannot** be `requires`d by a named module.
- An automatic module's name is the jar's file name minus version (`my-lib-1.2.jar` → `my.lib`), unless the jar's MANIFEST has `Automatic-Module-Name`.
- Reflection on a non-`opens` package fails with `IllegalAccessException` (or `InaccessibleObjectException` for `setAccessible`).
- `opens` implies the package is exported for **deep reflection** but *not* for compile-time access — for that you also need `exports`.
- `requires transitive java.base` is implicit and cannot be redeclared as transitive.
- Cyclic dependencies between named modules are forbidden (compile-time error).
- A module's `module-info.class` lives at the **root** of the module's class output.
- The `--describe-module` (or `-d`) flag of `java`/`jar` prints a module's descriptor.
- `--add-modules ALL-MODULE-PATH` makes every module on the path resolvable when launching.

## 4) Code Examples

### Named module declaration

```java
// src/com.namasoft.payments/module-info.java
module com.namasoft.payments {
    requires transitive com.namasoft.core;
    requires java.sql;
    requires static com.fasterxml.jackson.databind;   // optional at runtime

    exports com.namasoft.payments.api;
    exports com.namasoft.payments.internal to com.namasoft.web;

    opens com.namasoft.payments.entities to org.hibernate.orm;

    uses com.namasoft.payments.spi.Gateway;
    provides com.namasoft.payments.spi.Gateway
        with com.namasoft.payments.impl.StripeGateway;
}
```

### Layout

```
src/
 └── com.namasoft.payments/
     ├── module-info.java
     └── com/namasoft/payments/api/...
```

### Multi-module compilation

```bash
javac -d out --module-source-path src \
      $(find src -name "*.java")
```

### Run

```bash
java -p out -m com.namasoft.payments/com.namasoft.payments.Main
```

### `jdeps` examples

```bash
jdeps -s app.jar               # summary
jdeps --jdk-internals app.jar  # find usage of sun.* internals
jdeps --check com.namasoft.payments --module-path out
```

### Service consumption

```java
ServiceLoader.load(Gateway.class)
    .stream()
    .findFirst()
    .ifPresent(p -> p.get().charge(100));
```

## 5) Common Mistakes

- ❌ Forgetting that `exports` is required in addition to `public` to reach a type from another module.
- ❌ Treating `opens` as "exports for reflection" — it's *only* runtime/reflection. You still need `exports` for compile-time access.
- ❌ Splitting a package across two modules.
- ❌ Trying to `requires` an unnamed module (classpath jar) — impossible.
- ❌ Marking `requires transitive` on `java.base` (implicit).
- ❌ Cyclic `requires` between named modules.
- ❌ Misnaming an automatic module — depending on the jar filename means renaming the jar breaks consumers. Use `Automatic-Module-Name` in MANIFEST.
- ❌ Forgetting that `--add-modules` is needed for non-default modules at run time when they are not transitively required.
- ❌ Confusing `provides` with `exports` — services use both but they have different roles.
- ❌ Believing `opens` exposes private members across modules without `setAccessible(true)` — it doesn't; reflection still needs explicit access.

## 6) Mental Model

A module is like a **labeled container of packages with a manifest**:
- The manifest (`module-info.java`) lists what the module **needs** (`requires`) and what it **shows to others** (`exports`, `opens`).
- The compiler and runtime use that manifest to enforce strong encapsulation: even `public` is hidden if the package isn't exported.

Two distinct visibility axes:
1. **Compile-time** — controlled by `exports` (and `requires` to read).
2. **Runtime reflection** — controlled by `opens`.

The classpath becomes a **single unnamed module** for backward compatibility. Mixing classpath and module path is allowed but has subtle rules: unnamed code can read every module, but no module can require unnamed.

Services (`provides` / `uses` + `ServiceLoader`) are JPMS's way of decoupling implementation from interface across module boundaries — without exposing the implementation publicly.

## 7) Quick Revision

- Module = packages + descriptor (`module-info.java`).
- Every module implicitly `requires java.base`.
- `requires` reads; `exports` makes types visible at compile time.
- `requires transitive` provides implied readability.
- `requires static` = optional at runtime.
- `opens` exposes packages for reflection only.
- Three module kinds: **named**, **automatic** (jar on module path, no descriptor), **unnamed** (classpath).
- Split packages are illegal; cyclic requires are illegal.
- Automatic module name from jar file or MANIFEST `Automatic-Module-Name`.
- Tools: `javac`, `java`, `jar`, `jmod`, `jlink`, `jdeps`.
