# CH10 — Functional Programming (Streams)

## 1) Overview

Java's **Stream API** (added in Java 8 and steadily extended) is a declarative, lazy pipeline for processing elements of a source — typically collections, arrays, or generators. It is built on functional interfaces and pairs naturally with lambdas. The exam tests pipeline structure, intermediate vs. terminal operations, primitive streams, `Optional`, and the `Collectors` API.

---

## 2) Key Concepts

### Pipeline Structure

A stream pipeline has three parts:
1. **Source** — `collection.stream()`, `Arrays.stream(arr)`, `Stream.of(...)`, `Stream.iterate`, `Stream.generate`.
2. **Intermediate operations** — return a stream; they're **lazy**: nothing happens until a terminal op runs. `filter`, `map`, `flatMap`, `distinct`, `sorted`, `limit`, `skip`, `peek`.
3. **Terminal operation** — produces a result or side effect; closes the stream. `forEach`, `count`, `collect`, `toList`, `reduce`, `min`, `max`, `findFirst`, `findAny`, `anyMatch`, `allMatch`, `noneMatch`, `toArray`.

### Stream Properties

- **Lazy** — no work happens until a terminal op runs.
- **Single-use** — once consumed, a stream cannot be reused; `IllegalStateException` otherwise.
- **Functional** — operations should be stateless and side-effect-free for correctness, especially in parallel.
- **Possibly unbounded** — `Stream.iterate`/`generate` produce infinite streams; you must `limit(...)`.

### Optional

A container for a possibly-absent value. Key methods:
- `Optional.of(v)`, `Optional.ofNullable(v)`, `Optional.empty()`.
- `isPresent`, `ifPresent`, `ifPresentOrElse`.
- `get` (throws if empty — avoid in production), `orElse`, `orElseGet`, `orElseThrow`.
- `map`, `flatMap`, `filter`.

### Primitive Streams

`IntStream`, `LongStream`, `DoubleStream` avoid autoboxing and add numeric operations:
- `sum`, `average`, `min`, `max`, `summaryStatistics`.
- `mapToObj`, `mapToInt`, `mapToLong`, `mapToDouble`, `boxed`.
- `range(int, int)` (exclusive end), `rangeClosed(int, int)` (inclusive).

### Collectors

Stored in `java.util.stream.Collectors`:
- `toList`, `toUnmodifiableList`, `toSet`, `toMap(keyFn, valFn[, merger][, supplier])`.
- `joining([delim[, prefix, suffix]])`.
- `counting`, `summingInt`, `averagingInt`, `summarizingInt`.
- `groupingBy(classifier[, downstream])`, `partitioningBy(predicate[, downstream])`.
- `mapping`, `reducing`, `collectingAndThen`.

### Reduce

Three forms:
- `reduce(BinaryOperator)` → `Optional<T>`.
- `reduce(identity, BinaryOperator)` → `T`.
- `reduce(identity, BiFunction, BinaryOperator)` → `U` (parallel-friendly with combiner).

### Parallel Streams

- Created via `parallelStream()` or `stream().parallel()`.
- Operations should be **associative** and **stateless**.
- Order may not be preserved unless you call `forEachOrdered`.

## 3) Important Rules

- A stream can be consumed **once**. Calling another terminal op on the same stream throws `IllegalStateException: stream has already been operated upon or closed`.
- `peek` is intended for debugging — do not rely on it for side effects in production.
- `findAny` may not return the first element even on a sequential stream (typically does, but not guaranteed). Use `findFirst` for ordered semantics.
- `Stream.iterate(seed, f)` is infinite; `iterate(seed, hasNext, f)` (Java 9+) gives a bounded variant.
- `Optional.of(null)` throws `NullPointerException`. Use `ofNullable` for possibly-null values.
- `Optional.get()` on empty throws `NoSuchElementException`.
- `flatMap` flattens one level only — calling it on a `Stream<Stream<T>>` produces `Stream<T>`.
- `Collectors.toMap` throws `IllegalStateException` on duplicate keys unless you provide a merge function.
- Stream operations on a source generally see snapshot semantics for thread-safe collections, but mutating the source mid-pipeline is undefined.
- Primitive stream `sum()` returns the appropriate primitive (`int`/`long`/`double`); `average()` returns an `OptionalDouble`.
- `count()` on infinite streams **never terminates** unless preceded by a short-circuiting op.
- `limit` is short-circuiting; `skip` is not.
- A statement like `stream.filter(p)` with no terminal op is a **no-op** — the filter is never applied.

## 4) Code Examples

### Basic pipeline

```java
List<String> names = List.of("Mo", "Ali", "Yara", "Sara");
List<String> shortNames = names.stream()
    .filter(n -> n.length() < 4)
    .map(String::toUpperCase)
    .sorted()
    .toList();    // Java 16+: unmodifiable, ordered
```

### Reduce

```java
int sum = Stream.of(1, 2, 3, 4).reduce(0, Integer::sum);          // 10
Optional<Integer> max = Stream.of(3, 7, 2).reduce(Integer::max);  // Optional[7]
```

### Optional

```java
Optional<String> opt = Optional.ofNullable(getNullableName());
String safe = opt.map(String::toUpperCase).orElse("UNKNOWN");
```

### Grouping

```java
Map<Integer, List<String>> byLength =
    names.stream().collect(Collectors.groupingBy(String::length));
```

### Partitioning + downstream

```java
Map<Boolean, Long> evenOdd = IntStream.rangeClosed(1, 10).boxed()
    .collect(Collectors.partitioningBy(n -> n % 2 == 0, Collectors.counting()));
// {false=5, true=5}
```

### Primitive streams

```java
double avg = IntStream.rangeClosed(1, 100).average().orElse(0.0);
int sum   = IntStream.of(3, 1, 4, 1, 5, 9).sum();
```

### `flatMap`

```java
List<List<Integer>> nested = List.of(List.of(1,2), List.of(3,4));
List<Integer> flat = nested.stream()
    .flatMap(List::stream)
    .toList();   // [1, 2, 3, 4]
```

### Tricky: stream re-use

```java
Stream<Integer> s = Stream.of(1, 2, 3);
s.forEach(System.out::print);    // 123
s.forEach(System.out::print);    // ❌ IllegalStateException
```

### Tricky: infinite stream + count

```java
Stream.iterate(1, i -> i + 1).count();   // never returns!
Stream.iterate(1, i -> i + 1).limit(10).count();   // 10
```

### Tricky: `findFirst` on parallel

```java
List.of(1,2,3,4,5).parallelStream().findFirst();   // always Optional[1]
List.of(1,2,3,4,5).parallelStream().findAny();     // any element
```

### `toMap` with merge

```java
Map<Integer, String> byLen = Stream.of("a", "bb", "cc")
    .collect(Collectors.toMap(String::length, s -> s, (a,b) -> a + "," + b));
// {1=a, 2=bb,cc}
```

## 5) Common Mistakes

- ❌ Reusing a stream after a terminal op.
- ❌ Forgetting `.boxed()` when feeding an `IntStream` into a `Collector` for `Integer`.
- ❌ Calling `.count()` on infinite streams.
- ❌ Using `Optional.of(null)` — use `ofNullable`.
- ❌ Calling `.get()` on an `Optional` without checking `isPresent` (or using `orElse...`).
- ❌ Using stateful lambdas (modifying outer collections) — broken in parallel.
- ❌ Forgetting that `Collectors.toMap` errors on duplicate keys without a merge function.
- ❌ Treating `peek` as a stable mid-pipeline modifier; the JDK may skip elements that aren't needed for the terminal op.
- ❌ Confusing `flatMap` with `map` — `flatMap` *flattens* nested streams.
- ❌ Believing parallel streams are always faster — overhead can dominate small workloads.

## 6) Mental Model

A stream pipeline is **a recipe**, not a value. The recipe is built by chaining intermediate operations, each producing a new (lazy) stream. Nothing executes until the **terminal operation** sets the recipe in motion. Then elements flow one at a time through the entire pipeline (in many cases), enabling **short-circuiting** like `findFirst` and `limit`.

Three properties define correctness:
1. **Statelessness** — operations don't depend on hidden state.
2. **No side effects** — beyond the terminal one (which may collect or emit).
3. **Associativity** — for `reduce`, especially in parallel.

`Optional` is the *one-or-zero* analogue of a stream — `map`/`flatMap`/`filter` apply only when the value is present.

Primitive streams exist because `Stream<Integer>` would box every element. They aren't a separate hierarchy — just specialized classes (`IntStream`, etc.) with arithmetic conveniences.

---

## 7) Quick Revision

- Pipeline = source → intermediate ops → terminal op.
- Intermediate ops are **lazy**; nothing runs without a terminal op.
- Streams are **single-use**.
- `findFirst` is order-preserving; `findAny` is not (matters in parallel).
- `Stream.iterate(...)` is infinite — pair with `limit`.
- `Collectors.toMap` needs a merge function when duplicate keys are possible.
- `Optional.of(null)` → NPE; use `ofNullable`.
- `flatMap` flattens nested streams one level.
- Use `IntStream`/`LongStream`/`DoubleStream` to avoid boxing.
- `peek` is for debugging; `forEach`/`forEachOrdered` are terminal.
